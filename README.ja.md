# assume-nothing

**AIは「思い込まない」と約束した。これでもう、思い込めない。**

Claude Code 用のプラグインです（Cursor・Codex CLI・Gemini CLI・OpenCode にも試験対応）。AIに「動く前に必ず見る」をさせます。2つの層でできています。

**本体：マシンについての事実（確実。常に有効）**

1. **最初に下調べ**：会話が始まると、パソコンと作業フォルダを調べて、「確認済み」「入っていない」「不明」に分けた短い一覧をAIに渡します。プロジェクトが求める版（`go.mod`、`.nvmrc`、`package.json` の engines、`.python-version` など）と入っている版が食い違っていれば、「MISMATCH（食い違い）」として伝えます。
2. **下調べが無ければ道具は使えない**：下調べが済むまで、AIの道具の使用をすべて止めます。止めた理由と一緒に下調べの結果を返すので、AIはそれを読んで続けられます。
3. **入っていないコマンドは実行させない**：入っていないコマンドを実行しようとしたら、実行前に止めて、代わりに入っているものを伝えます。

ここは推測ではなく確認です。コマンドがあるか無いか、版が合うか合わないかは、はっきり決まります。

**調べたかの確認：聞いた相手についての事実（推測を含む。初期は有効、調整できる）**

4. **聞いた相手について、記憶だけで答えさせない**：`なにかのライブラリ` や `owner/repo` について聞くと、AIに「これについてはまだ何も分かっていない」と伝えます。それでも何も調べずに答えたら、答えを一度だけ差し戻します（調べ直すか、未確認だとはっきり書かせる）。

この層は「依頼のどの言葉が名前か」「道具がそれを見たか」を推測で判断するので、両方向に間違えることがあります。`.assume-nothing.json` に `"lookup": "note"`（注意書きだけで差し戻さない）や `"off"` を書けば弱められます。

![assume-nothing なし・ありの比較。なしでは `python` を打って失敗し、ありでは下調べで `python3` しか無いと分かって一発で成功する](docs/demo/demo.gif)

## なぜ作ったか

Karpathy 氏の考えをまとめた `CLAUDE.md` のような指示書は、AIに「書く前に考えろ」「思い込むな」とお願いします。ただのお願いなので、AIが読み飛ばすことがあります。

フック（AIの外側で動く仕組み）なら読み飛ばせません。`assume-nothing` は「思い込むな」を、お願いから仕組みに変えます。

下調べに意味があることを示す研究もあります。[Meta-Harness 論文](https://arxiv.org/abs/2603.28052)（Stanford ほか、2026年）では、AIの動かし方を自動で改良していった結果、「最初の一手の前に環境の一覧を渡す」という改良が見つかりました。Terminal-Bench 2 という試験で、Claude Opus 4.6 では 74.7% → 76.4%、Claude Haiku 4.5 では 33.7% → 37.6% でした。下調べが無いとき、AIは最初の2〜4手を「何が入っているか探る」ことに使っていたそうです。ただし論文は下調べだけを外した比較をしていないので、参考値として見てください。

## 調べる相手についても、思い込ませない

下調べ（probe）が守るのは「自分のマシン」です。「思い込むな」のもう半分は「聞かれた相手」、たとえばライブラリの最新版、リポジトリの中身、ファイルに何が書いてあるか、です。AIはこれを記憶で答えがちで、記憶は古くなります。

依頼の中に名前が出てくると、AIは作業の前にこう伝えられます。

```text
[assume-nothing: targets]
This request is about: orbit-labs/quasar-cli.
（これについての事実は、この会話の中で一次情報を見るまで「不明」。記憶は古いか間違っているかもしれない。
 調べずに事実を書いた答えは一度止める）
```

道具を使うたびに、その名前に触れたか（ページを開いた、検索した、ファイルを読んだ、コマンドの入出力に出てきた）を記録します。失敗した取得（エラー、403、回数制限、空の返事）や、サブエージェントへの丸投げは「調べた」に数えません。AIが答えを終えようとしたとき、名前の出た相手について何も見ていないのに答えていたら、一度だけ差し戻します。名前のすぐ近くに「未確認です」と書いてある答えは通します。

「最新版」「料金」のように時期で変わる質問は、名前が拾えなくても、その回の中で一度は調べる必要があります。記憶では答えられない質問なので、「未確認」と書いてあっても最初の1回は差し戻します。実際に動かしたところ、Claude Haiku が記憶で「Bun の最新は 1.3.4」と答えて差し戻され、調べ直して 1.4.4 に訂正しました。

名前として拾うもの：`owner/repo`、URL、`ハイフン-つきの-名前`・`点.つき`、`` `バッククォート` `` や「かぎかっこ」で囲んだ名前、「〜について」「〜とは」「〜を調べて」の直前の英字・カタカナ・漢字まじりの名前（「秀丸エディタ」など。「ライブラリ」「ログ」「原因」のような一般的な言葉は除く）、中国語（关于X、X是什么）、韓国語（X에 대해）。漢字だけの名前は、ふつうの言葉と区別できないため「」で囲んだときに拾います（例：「一太郎」）、"research" "look up" "what is" の直後の語。文中のふつうの単語は拾いません。

サブエージェントの答えも同じように確かめます。差し戻したときや、コマンドを止めたときは、AIだけでなく利用者の画面にも1行のお知らせが出ます。何をしたかは、AIに `assume-nothing status` を実行してもらうと一覧で見られます（下調べの内容、止めたコマンド、調べた名前と方法、差し戻した回数）。

![Bun の最新版を聞かれ、記憶で 1.3.4 と答えて一度差し戻され、検索して 1.4.4 に直す様子](docs/demo/demo-lookup.gif)

正直に言うと、確かめているのは「見たかどうか」で、「答えが正しいかどうか」ではありません。実際に動かしたところ、最初の一言だけでたいてい効き、AIは先に検索するか、「記憶で答えます（未確認）」と最初に断るようになりました。

## 追加オプション：言葉のチェック

「調べたかの確認」は、依頼に出てきた名前しか見ません。依頼に出てこなかったことを答えの中で言い切った場合は、小さいAIに最後の答えを読ませて、出典のない言い切り（版数・価格・初期値・フラグ・関数名など）を見つける「言葉のチェック」を追加できます。

```sh
assume-nothing install-text-check          # このプロジェクトだけ
assume-nothing install-text-check --user   # すべてのプロジェクト
assume-nothing install-text-check --remove # 外す
```

答えのたびに小さいAIを1回呼ぶので費用がかかるため、入れたときだけ動きます。実際に動かしたところ、「Node.js の最新LTSは24系」という言い切りを見つけ、AIが公式サイトを見て26系に訂正しました。

## 比較試験

同じ作業を、同じAIで、あり・なしで比べました。作業はどれも架空の小さなプロジェクトです。各10回ずつ、ほかのプラグインが無い状態で実行しました（2026-10-30）。

**入っていない道具**：プロジェクトが、入っていない道具を使いそうに見える作業（`pnpm` の記録ファイルがあるのに `npm` だけ、Makefile があるのに `make` が無い、README は `python` なのに `python3` だけ、動画の長さを聞くのに `ffprobe` が無い）。

| AI | プラグイン | 成功 | 入っていない道具を叩いた失敗（1作業あたり） | 道具の使用回数 |
| --- | --- | --- | --- | --- |
| Claude Haiku | なし | 40/40 | 0.9 | 3.9 |
| Claude Haiku | **あり** | 40/40 | **0.0** | 3.5 |
| Claude Sonnet | なし | 40/40 | 0.6 | 2.8 |
| Claude Sonnet | **あり** | 40/40 | **0.0** | 2.9 |

**記憶では分からない事実**：答えがプロジェクト内の資料にしか書いていない架空の道具について、3種類の質問（どこを見ればいいかは言わない）。

| AI | プラグイン | 正解 | 間違った事実 | 答えなし |
| --- | --- | --- | --- | --- |
| Claude Haiku | なし | 24/30 | 2 | 4 |
| Claude Haiku | **あり** | **30/30** | 0 | 0 |
| Claude Sonnet | なし | 20/30 | 1 | 9 |
| Claude Sonnet | **あり** | **30/30** | 0 | 0 |

正直に書くと：

- 1つ目の試験は、どちらも全部成功です。変わったのは途中の動き方で、ありだと無い道具を叩かなくなりました。
- 2つ目の試験で、なしの失敗の多くは嘘ではなく「あきらめ」でした。「zorvexmark の最新版は？」に対して公開サイトが 404 を返すと、そこで止まることが多かったのです。ありでは「まずこのプロジェクトの中を見る」と伝えるので、同梱の更新履歴を見つけて正解しました。その分、道具の使用は少し増えます。
- 「調べろ」とだけ伝える版（v0.10）は逆効果でした（Haiku ありで 21/30）。AIがまずインターネットを探しに行ったためです。v0.11 で「まずプロジェクト内」に直し、上の数字は v0.11 のものです。
- 罠を入れた作業で測っているので、普段の作業で同じ数字が出るとは限りません。

## 入れ方

Claude Code で次の2行を実行し、新しい会話を始めます。

```text
/plugin marketplace add kajisho5/assume-nothing
/plugin install assume-nothing@assume-nothing
```

Claude アプリ（ブラウザ・デスクトップ・iPhone で、AIがクラウドのマシンで作業する会話）で使う場合:

アカウントに1回追加すれば、その種類の会話と Claude Code に同期されます。[claude.ai/customize/plugins](https://claude.ai/customize/plugins) を開いて **追加（Add）→ プラグインをアップロード（Upload plugin）** を押し、[最新リリース](https://github.com/kajisho5/assume-nothing/releases/latest) の `assume-nothing-plugin.zip` を選びます。追加したあとに新しい会話を始めてください。普通のチャットはプラグインのフックを動かさない（コマンドも打たない）ので、そこでは出番がありません。

クラウド版の Claude Code（ブラウザや iPhone の Claude アプリから使うもの）と、チーム全員で使う場合:

クラウド版はプラグインを入れませんが、リポに書いてあるフックは動かします。リポごとに1回、そのリポで開いた会話（iPhone から始めたクラウドの会話でも可）で、AIに次を実行してもらい、追加されたファイルをコミットしてもらいます。

```sh
curl -fsSL https://raw.githubusercontent.com/kajisho5/assume-nothing/main/scripts/setup.sh | sh -s repo
```

追加されるのは `.claude/assume-nothing/run.sh` と、`.claude/settings.json` の6つのフックです。以後、そのリポで開く Claude Code はすべて、最初に下調べをします（クラウド、自分のパソコン、チームの人）。最初の1回だけ、その機械に合った実行ファイルを GitHub から取ってきて、改ざんがないか確かめてから使います。うまくいかないときは黙って通すので、AIが動けなくなることはありません。外すときは `.claude/assume-nothing/run.sh install-repo --remove`。

条件：クラウドの会話がそのリポ1つだけを開いていること。GitHub への通信が許可されていること（標準の「Trusted」設定なら許可されています）。

Cursor（試験対応）:

```sh
curl -fsSL https://raw.githubusercontent.com/kajisho5/assume-nothing/main/scripts/setup.sh | sh -s cursor
```

Windows（PowerShell。Git Bash 不要）では `& ([scriptblock]::Create((irm https://raw.githubusercontent.com/kajisho5/assume-nothing/main/scripts/setup.ps1))) cursor`（`opencode`・`repo` も同じ書き方）。

`~/.cursor/hooks.json` に追加され、すべてのプロジェクトで動きます（今あるフックはそのまま。外すときは `... | sh -s cursor --remove`）。

OpenCode（試験対応）:

```sh
curl -fsSL https://raw.githubusercontent.com/kajisho5/assume-nothing/main/scripts/setup.sh | sh -s opencode
```

最初の道具の使用を下調べ付きで止めることと、入っていないコマンドを止めることができます。OpenCode には「答えが確定する前」に割り込める公開された仕組みがないため、調べずに答えたときの差し戻しは使えません。

Codex CLI（試験対応）:

```sh
codex plugin marketplace add kajisho5/assume-nothing@dist
codex plugin add assume-nothing@assume-nothing
```

Gemini CLI（試験対応）:

```sh
gemini extensions install https://github.com/kajisho5/assume-nothing --ref gemini
```

Codex・Gemini・Cursor・OpenCode は、形式の検査（OpenCode は Node での動作確認）までは済んでいます。実際の会話の中で動かす確認はまだです。

## しないこと

- 「許可」は出しません。いつもの確認画面はそのままです。
- プロジェクトのファイルの中身、環境変数の値、パスワードは読みません（例外は、版の食い違いを見るための「版の指定」部分だけ。`go.mod`、`.nvmrc`、`package.json` の engines など）。名前と有無だけを記録します（読むのは自分の設定ファイル `.assume-nothing.json` と、OSの情報ファイルだけ。変更数を数えるため `git status` は実行します）。
- どこにも送信しません（`deep net` は、AIが頼んだときだけ github.com・pypi.org・registry.npmjs.org に接続確認を送ります）。
- 自分の仕事ができないとき（中の不具合、実行ファイルが無い、記録が保存できない）は、止めずに通します。止めたことを記録できないと永久に止め続けてしまうため、その場合は注意を伝えるだけにします。記録できなくても止め続けたい場合は `ASSUME_NOTHING_STRICT=1`。
- Mac で、開発ツール未導入のときに `/usr/bin` にある「インストール画面を出すだけの仮のコマンド」（`git`、`python3` など）は、入っていない扱いにし、実行もしません。
- 答えが正しいかどうかは確かめません。確かめるのは「何かで調べたか」だけです。
- 調べたかの判定のために、依頼文・道具の入出力・最後の答えをその場で読みますが、保存するのは拾った名前だけです。
- 安全のための壁ではありません。フックを通らない道具もあります。Codex ではクラウド側の Web 検索がフックを通らないため、それだけで調べた場合は一度差し戻され、どこで読んだかを書けば通ります。

## 設定

作業フォルダに `.assume-nothing.json` を置きます。

```json
{
  "tools": ["blender", "ffprobe", "wrangler"],
  "skip": ["docker"],
  "lookup": "note"
}
```

| 項目 | 意味 |
| --- | --- |
| `tools` | 最初の下調べで追加で確認する道具 |
| `skip` | 下調べから外す言語・道具・パッケージ管理 |
| `lookup` | 調べたかの確認：`send-back`（初期値。差し戻しまでする）、`note`（注意書きだけで差し戻さない）、`off`（使わない） |

環境変数 `ASSUME_NOTHING_LOOKUP=send-back|note|off` でも切り替えられます（ファイルより優先）。全部止めたいときは `ASSUME_NOTHING=off`。

お知らせや差し戻しの文は、依頼が日本語なら日本語で出ます。言語を固定したいときは `ASSUME_NOTHING_LANG=ja`（または `en`）。

## 仕組み

| いつ | 何をするか |
| --- | --- |
| 会話の開始・再開・圧縮のあと | マシンと作業フォルダを下調べ（2秒以内）し、版の食い違いも調べてAIに渡す |
| 依頼が来たとき | 依頼に出てくる名前を拾い、「調べるまで不明」とAIに伝える。下調べがまだなら、ここで下調べする |
| 道具を使う前 | 下調べが無ければ、下調べを付けて一度止める。入っていないコマンドなら一度止める（2回目は通す）。`npm i -g pnpm && pnpm …` のように入れてすぐ使う行で、入れ先のフォルダが PATH に無いときも、フルパスを添えて一度止める。作業フォルダが変わったら調べ直す。起動直後に時間切れになった言語は、最初の1回だけ時間を長めにして調べ直す |
| 道具を使ったあと | その道具が名前を見たかを記録する。インストールのコマンドなら、入っているものを調べ直す |
| AI（またはサブエージェント）が答えを終えるとき | 名前の出た相手について何も見ずに答えていたら、一度だけ差し戻し、利用者にも1行で知らせる |

## 困ったとき

- **動いているか知りたい**：AIに `assume-nothing status` を実行してもらいます（下調べの「Deeper checks」の行にあるパスの `deep` を `status` に変える）。下調べの内容、止めたコマンド、調べた名前と方法、差し戻した回数が出ます。下調べが無ければ、フックが動いていません。
- **Claude アプリで何も起きない**：道具を使わない普通のチャットでは動きません。AIが作業する会話で、アカウントに入れたプラグインが最新版か確認してください（自動では新しくなりません）。
- **言語が「signal: killed」で不明になる**：起動直後でマシンが重かったためです。最初に道具を使うときに、時間を長めにして調べ直します。
- **あるはずのコマンドを止められた**：同じコマンドをもう一度実行すれば通ります。`node_modules/.bin` や `.venv/bin` にある道具なら、実行のしかたを案内します。
- **差し戻しが厳しすぎる**：`.assume-nothing.json` に `"lookup": "note"`、または `ASSUME_NOTHING_LOOKUP=note`。
- **一時的に全部止めたい**：`ASSUME_NOTHING=off`。
- **記録の場所**：プラグインのデータフォルダ（`CLAUDE_PLUGIN_DATA`）か `ASSUME_NOTHING_DATA`。30日で消えます。

## 動く環境

- Mac・Linux・Windows（amd64 / arm64）。Windows の Claude Code と Codex は Git Bash 経由で動きます（無い場合は止めずに素通り）。Cursor と OpenCode は Git Bash 不要です
- ほかのソフトは不要です（Go で作った実行ファイル1つ）
