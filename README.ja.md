# assume-nothing

**AIは「思い込まない」と約束した。これでもう、思い込めない。**

Claude Code 用のプラグインです（Codex CLI・Gemini CLI にも試験対応）。AIに「動く前に必ず見る」をさせます。

1. **最初に下調べ**：会話が始まると、パソコンと作業フォルダを調べて、「確認済み」「入っていない」「不明」に分けた短い一覧をAIに渡します。
2. **下調べが無ければ道具は使えない**：下調べが済むまで、AIの道具の使用をすべて止めます。止めた理由と一緒に下調べの結果を返すので、AIはそれを読んで続けられます。
3. **入っていないコマンドは実行させない**：入っていないコマンドを実行しようとしたら、実行前に止めて、代わりに入っているものを伝えます。

![assume-nothing なし・ありの比較。なしでは `python` を打って失敗し、ありでは下調べで `python3` しか無いと分かって一発で成功する](docs/demo/demo.gif)

## なぜ作ったか

Karpathy 氏の考えをまとめた `CLAUDE.md` のような指示書は、AIに「書く前に考えろ」「思い込むな」とお願いします。ただのお願いなので、AIが読み飛ばすことがあります。

フック（AIの外側で動く仕組み）なら読み飛ばせません。`assume-nothing` は「思い込むな」を、お願いから仕組みに変えます。

下調べに意味があることを示す研究もあります。[Meta-Harness 論文](https://arxiv.org/abs/2603.28052)（Stanford ほか、2026年）では、AIの動かし方を自動で改良していった結果、「最初の一手の前に環境の一覧を渡す」という改良が見つかりました。Terminal-Bench 2 という試験で、Claude Opus 4.6 では 74.7% → 76.4%、Claude Haiku 4.5 では 33.7% → 37.6% でした。下調べが無いとき、AIは最初の2〜4手を「何が入っているか探る」ことに使っていたそうです。ただし論文は下調べだけを外した比較をしていないので、参考値として見てください。

## 比較試験

同じ作業を、同じAIで、あり・なしで比べました。作業はどれも、架空の小さなプロジェクトに「罠」を入れたものです。

- `pnpm` の記録ファイルがあるのに `npm` しか入っていない
- Makefile があるのに `make` が無い
- README は `python` と言うのに `python3` しか無い
- 動画の長さを聞くのに `ffprobe` が無い

4種類の作業を、それぞれ3回ずつ実行しました（2026-10-29）。

| AI | 下調べ | 成功 | 入っていない道具を叩いた失敗（1作業あたり） | 道具の使用回数 | 秒 |
| --- | --- | --- | --- | --- | --- |
| Claude Haiku | なし | 12/12 | 1.3 | 4.2 | 14 |
| Claude Haiku | **あり** | 12/12 | **0.1** | **3.2** | **12** |
| Claude Sonnet | なし | 12/12 | 0.8 | 3.1 | 14 |
| Claude Sonnet | **あり** | 12/12 | **0.0** | **2.8** | **11** |

正直に言うと、成功率はどちらも全部成功で、差はありません。変わったのは途中の動き方です。下調べがあると、無い道具を叩かなくなるので、手数が減って早く終わります。小さいAIほど効果が大きく出ました。ただし回数が少なく、罠入りの作業だけで測っているので、普段の作業で同じ数字が出るとは限りません。

## 入れ方

Claude Code で次の2行を実行し、新しい会話を始めます。

```text
/plugin marketplace add kajisho5/assume-nothing
/plugin install assume-nothing@assume-nothing
```

Codex CLI（試験対応）:

```sh
codex plugin marketplace add kajisho5/assume-nothing@dist
codex plugin add assume-nothing@assume-nothing
```

Gemini CLI（試験対応）:

```sh
gemini extensions install https://github.com/kajisho5/assume-nothing --ref gemini
```

Codex と Gemini は、インストールと形式の検査までは確認済みです。実際の会話の中で動かす確認はまだです。

## しないこと

- 「許可」は出しません。いつもの確認画面はそのままです。
- プロジェクトのファイルの中身、環境変数の値、パスワードは読みません。名前と有無だけを記録します（読むのは自分の設定ファイル `.assume-nothing.json` と、OSの情報ファイルだけ。変更数を数えるため `git status` は実行します）。
- どこにも送信しません（`deep net` は、AIが頼んだときだけ github.com・pypi.org・registry.npmjs.org に接続確認を送ります）。
- 自分の仕事ができないとき（中の不具合、実行ファイルが無い、記録が保存できない）は、止めずに通します。止めたことを記録できないと永久に止め続けてしまうため、その場合は注意を伝えるだけにします。記録できなくても止め続けたい場合は `ASSUME_NOTHING_STRICT=1`。
- Mac で、開発ツール未導入のときに `/usr/bin` にある「インストール画面を出すだけの仮のコマンド」（`git`、`python3` など）は、入っていない扱いにし、実行もしません。
- 安全のための壁ではありません。フックを通らない道具もあります。

## 設定

プロジェクトで必ず使う道具は、作業フォルダの `.assume-nothing.json` に書くと、最初の下調べで確認されます。

```json
{ "tools": ["blender", "ffprobe", "wrangler"] }
```

## 動く環境

- Mac・Linux（amd64 / arm64）、Windows は Git Bash がある場合
- ほかのソフトは不要です（Go で作った実行ファイル1つ）
